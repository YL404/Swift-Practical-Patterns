# Liquid Glass containers, unions, and transitions

Use this reference when custom views styled with `glassEffect(_:in:)` need to blend, merge across gaps, or animate in and out together. For circular glass system buttons and concentric corner shapes, see [control-shapes.md](control-shapes.md).

Apple documentation and SDK interfaces verified 2026-11-24. [`GlassEffectContainer`](https://developer.apple.com/documentation/swiftui/glasseffectcontainer), [`glassEffect(_:in:)`](https://developer.apple.com/documentation/swiftui/view/glasseffect(_:in:)), [`glassEffectUnion(id:namespace:)`](https://developer.apple.com/documentation/swiftui/view/glasseffectunion(id:namespace:)), [`glassEffectID(_:in:)`](https://developer.apple.com/documentation/swiftui/view/glasseffectid(_:in:)), and [`glassEffectTransition(_:)`](https://developer.apple.com/documentation/swiftui/view/glasseffecttransition(_:)) require an SDK exposing iOS 26 / macOS 26 / tvOS 26 / watchOS 26 APIs and are marked unavailable on visionOS. Always gate usage with `#available` and retain an ordinary non-glass fallback for earlier runtimes.

## Scope `GlassEffectContainer` deliberately

`GlassEffectContainer` extracts Liquid Glass shapes from its descendants and renders them together so nearby glass shapes can blend and morph while avoiding redundant per-view rendering passes. It does not lay out its children; arrange them with `HStack`, `VStack`, or another layout container inside it, and apply `.glassEffect(_:in:)` to each custom glass view after layout and appearance modifiers (such as padding and font). [Applying Liquid Glass to custom views](https://developer.apple.com/documentation/swiftui/applying-liquid-glass-to-custom-views)

- **Skip the container for system chrome:** standard controls such as toolbars and tab bars already manage Liquid Glass grouping internally; do not wrap them in a manual `GlassEffectContainer`.
- **Skip the container for unrelated standalone surfaces:** having multiple glass views on screen does not require grouping them if they should stay visually independent and far apart.
- **Keep onscreen glass count and container count bounded:** Apple explicitly warns that creating too many `GlassEffectContainer` instances or applying too many `glassEffect` views outside containers degrades rendering performance. [Performance guidance](https://developer.apple.com/documentation/swiftui/applying-liquid-glass-to-custom-views)

## Separate proximity blending (`spacing`) from explicit unions

`GlassEffectContainer(spacing:)` does not set layout spacing between views. It sets the proximity threshold at which glass shapes begin to pull toward and blend with one another, as well as the range within which default morphing transitions match nearby shapes. [GlassEffectContainer](https://developer.apple.com/documentation/swiftui/glasseffectcontainer)

- **At rest versus transitioning:** Apple notes that a container `spacing` larger than an interior `HStack`/`VStack` spacing causes glass shapes to blend together at rest. A smaller or omitted (`nil`) container `spacing` keeps resting views separate until they approach one another. Do not assume an undocumented fixed multiplier between layout gap and visual join point; check the rendered result in your actual layout.
- **Merge across arbitrary gaps with `glassEffectUnion(id:namespace:)`:** when separate views—such as items generated by `ForEach` or positioned outside a tight stack—should render as one unified glass shape even at rest, place them in the same `GlassEffectContainer` and attach `.glassEffectUnion(id:namespace:)` after `.glassEffect(_:in:)` using a shared ID and `@Namespace`. Apple documents that unioning combines effects sharing the **same shape and `Glass` variant** as well as the same union ID and namespace. [glassEffectUnion(id:namespace:)](https://developer.apple.com/documentation/swiftui/view/glasseffectunion(id:namespace:))

Complete view definition for iOS 26+ / macOS 26+ showing a unified formatting group beside a separate destructive action inside one container. Actions are placeholders supplied by the caller. `.buttonStyle(.plain)` suppresses default platform button chrome (such as macOS push-button bezels) when styling a custom control directly with `.glassEffect(_:in:)`; for standalone system glass buttons that do not need manual unioning or morphing, prefer `.buttonStyle(.glass)` per [control-shapes.md](control-shapes.md).

```swift
import SwiftUI

@available(iOS 26.0, macOS 26.0, *)
struct GlassFormatToolbar: View {
    let onBold: () -> Void
    let onItalic: () -> Void
    let onDelete: () -> Void

    @Namespace private var glassNamespace

    var body: some View {
        GlassEffectContainer(spacing: 16) {
            HStack(spacing: 28) {
                Button(action: onBold) {
                    Label("Bold", systemImage: "bold")
                        .labelStyle(.iconOnly)
                        .frame(width: 44, height: 44)
                        .contentShape(.capsule)
                }
                .buttonStyle(.plain)
                .glassEffect(.regular.interactive(), in: .capsule)
                .glassEffectUnion(id: "format", namespace: glassNamespace)

                Button(action: onItalic) {
                    Label("Italic", systemImage: "italic")
                        .labelStyle(.iconOnly)
                        .frame(width: 44, height: 44)
                        .contentShape(.capsule)
                }
                .buttonStyle(.plain)
                .glassEffect(.regular.interactive(), in: .capsule)
                .glassEffectUnion(id: "format", namespace: glassNamespace)

                Button(role: .destructive, action: onDelete) {
                    Label("Delete", systemImage: "trash")
                        .labelStyle(.iconOnly)
                        .frame(width: 44, height: 44)
                        .contentShape(.capsule)
                }
                .buttonStyle(.plain)
                .glassEffect(.regular.interactive(), in: .capsule)
            }
        }
    }
}
```

## Choose the glass transition explicitly and verify `glassEffectID` behavior

[`glassEffectTransition(_:)`](https://developer.apple.com/documentation/swiftui/view/glasseffecttransition(_:)) and [`glassEffectID(_:in:)`](https://developer.apple.com/documentation/swiftui/view/glasseffectid(_:in:)) only take effect during view-hierarchy insertions, removals, or animated state changes inside a `GlassEffectContainer`. Choose the [`GlassEffectTransition`](https://developer.apple.com/documentation/swiftui/glasseffecttransition) deliberately:

| Transition | Use when | Behavior contract |
|---|---|---|
| `.matchedGeometry` (default) | An appearing or disappearing glass view sits within the container's `spacing` of an existing glass shape and should grow out of or shrink into it. | Derives transition geometry from a nearby shape in the container. Apple also documents that default behavior applies extra scale and offset animations when a shape keeps its identity while its content changes; provide an explicit animation such as `.spring` to opt out. [matchedGeometry](https://developer.apple.com/documentation/swiftui/glasseffecttransition/matchedgeometry) |
| `.materialize` | The glass view is farther away than the container's `spacing`, or should appear and disappear in place instead of emerging from a neighbor. | Fades content and animates the glass material in place without matching another glass shape's geometry. [materialize](https://developer.apple.com/documentation/swiftui/glasseffecttransition/materialize) |
| `.identity` | No glass transition animation is wanted. | Disables glass transition changes. [identity](https://developer.apple.com/documentation/swiftui/glasseffecttransition/identity) |

Apple's guide assigns each participating glass view a **unique** `glassEffectID(_:in:)` within a shared `@Namespace` inside `GlassEffectContainer`, combined with `withAnimation`, so SwiftUI tracks individual shapes across hierarchy updates. In iOS 27.2 SDK declarations, `id` must be `(some Hashable & Sendable)?`; `GlassEffectContainer`, `glassEffectUnion`, and `glassEffectTransition` are `@MainActor @preconcurrency`, while `glassEffect` and `glassEffectID` are `nonisolated`.

Treat cross-screen morphing conservatively: the source article reported on iOS 27 that nearby sibling appearance inside a `GlassEffectContainer` morphed visually even without `glassEffectID`, whereas pairing distant opposing-corner controls with `glassEffectID` snapped in one frame rather than flying across the screen. Do not assume `glassEffectID` guarantees arbitrary long-distance morphs; use `.materialize` for distant appearances and visually verify animated transitions on the target OS runtime.

Complete iOS 26+ / macOS 26+ view definition demonstrating unique IDs inside a container and an explicit `.materialize` override for an independent auxiliary badge. The expanded symbols stand in for real tool controls or status badges.

```swift
import SwiftUI

@available(iOS 26.0, macOS 26.0, *)
struct ExpandableGlassTools: View {
    @State private var isExpanded = false
    @Namespace private var glassNamespace

    var body: some View {
        GlassEffectContainer(spacing: 24) {
            HStack(spacing: 16) {
                Button {
                    withAnimation {
                        isExpanded.toggle()
                    }
                } label: {
                    Image(systemName: isExpanded ? "xmark" : "pencil")
                        .frame(width: 44, height: 44)
                        .contentShape(.circle)
                }
                .buttonStyle(.plain)
                .accessibilityLabel(isExpanded ? "Collapse tools" : "Expand tools")
                .glassEffect(.regular.interactive(), in: .circle)
                .glassEffectID("toggle", in: glassNamespace)

                if isExpanded {
                    Image(systemName: "eraser")
                        .frame(width: 44, height: 44)
                        .glassEffect(.regular, in: .circle)
                        .glassEffectID("eraser", in: glassNamespace)

                    Image(systemName: "sparkles")
                        .frame(width: 44, height: 44)
                        .glassEffect(.regular, in: .circle)
                        .glassEffectID("status", in: glassNamespace)
                        .glassEffectTransition(.materialize)
                }
            }
        }
    }
}
```

## Verification and remaining boundaries

Both examples were extracted verbatim and passed `swiftc -typecheck` with Xcode 27.2 (27B52), Apple Swift 6.4.2 (swiftlang-6.4.2.1.9), the iPhoneOS 27.2 SDK targeting arm64 iOS 26.0, and the macOS 27.2 SDK targeting arm64 macOS 26.0. Checks covered Swift 6 with both `nonisolated` and `MainActor` default isolation plus Swift 5 with `nonisolated` default isolation, complete strict concurrency, and warnings as errors. SDK `.swiftinterface` declarations confirmed availability (`iOS 26.0, macOS 26.0, tvOS 26.0, watchOS 26.0`, `visionOS` unavailable), `@MainActor`/`nonisolated` annotations, and `Hashable & Sendable` ID constraints.

No UI was rendered or visually inspected locally. Optical blending thresholds for `spacing`, `glassEffectUnion` visual joining, `.matchedGeometry` versus `.materialize` motion curves, `glassEffectID` runtime behavior across distances, Reduce Transparency, contrast, hit targets, and GPU rendering cost must be checked on a simulator or physical device running the target OS.

# Repository instructions

This repository maintains the canonical Swift Practical Patterns skill. It provides focused Swift and SwiftUI guidance that can be used alongside community skills.

- Keep all project content, filenames, and commit messages in English.
- Keep `SKILL.md` concise. Route tasks to focused references and read only the references needed for the current task.
- Add guidance that changes an implementation decision. Check the existing content and relevant community skills before adding or replacing advice.
- For new guidance and substantive revisions, prepare the draft, source verification, and proportionate validation outside this repository. The reviewer accepts individual knowledge points before applying them to the canonical package, including through symlinks. A single agent may write and review in separate stages; do not describe self-review as independent review. Spelling or formatting fixes that preserve meaning may be edited directly and still require a diff review.
- Integrate accepted findings into the relevant scenario guidance. Review the complete affected scenario, consolidate repetition, and correct conflicting or obsolete advice while preserving applicable version branches and essential implementation details. Avoid per-article or dated summary appendices; length, file counts, and source counts are not quality measures.
- Read original articles and matching Apple or Swift sources when verifying claims. Distinguish official constraints, implementation advice, and observed behavior.
- Preserve platform, SDK, language-mode, configuration, and lifecycle requirements beside the affected guidance.
- Keep examples minimal and identify placeholders or incomplete implementations.
- Record verification dates and actual validation conditions. Distinguish compilation, local execution, simulator checks, device behavior, synchronization, and performance.
- Keep blog attribution in a short `Sources` section at the end of each reference. Link official evidence beside the claim it supports. Use full source URLs.
- Keep the installed skill self-contained. Keep article archives, drafts, review logs, and machine-specific paths outside this repository.
- Validate skill metadata, relative links, Markdown fences, and the complete diff after integration. Recheck affected claims or examples if review changes them. Run checks proportionate to technical changes; formatting changes do not require rerunning unrelated examples.
- Preserve unrelated work. Stage only the current change and obtain explicit authorization before publishing or pushing.
